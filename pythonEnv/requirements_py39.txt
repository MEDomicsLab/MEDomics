#   conda install "openssl=3.0.20" -y          # <-- REQUIRED, see below

# -----------------------------------------------------------------------------
# REQUIRED CONDA STEP - openssl must be pinned to 3.0.x
# -----------------------------------------------------------------------------
# conda now ships OpenSSL 3.5.x by default. OpenSSL 3.5 changed the error it
# reports at end-of-data when parsing DER certificates from ASN1_R_HEADER_TOO_LONG
# to ASN1_R_NOT_ENOUGH_DATA. CPython 3.9's _ssl.c only recognises the old reason
# as "clean EOF", so on Windows `ssl.create_default_context()` - which loads the
# Windows cert store as DER - dies with:
#
#     ssl.SSLError: [ASN1: NOT_ENOUGH_DATA] not enough data (_ssl.c:4192)
#
# CPython 3.11+ carries the fix; 3.9 does not, and 3.9 is EOL so it never will.
# tornado calls create_default_context() at import time, so this takes down
# tornado -> distributed -> dask.distributed -> lightgbm -> pycaret.setup().
# lightgbm's dask import guard only catches ImportError, so the SSLError escapes.
#
# This cannot be expressed as a pip requirement: openssl is a conda-level native
# library that CPython's _ssl module links against, not a Python package.
#
#     conda install -n <env> "openssl=3.0.20" -y
#
# Use 3.0.20, NOT 3.0.21 - the 3.0.21 build carries a `python >=3.10` constraint
# and conda satisfies it by removing Python 3.9 from the environment.
#
# Strictly this only bites on Windows: _load_windows_store_certs (the DER path)
# is guarded by `sys.platform == "win32"`, while Linux/macOS go through
# set_default_verify_paths() and read PEM. Pinning on all platforms anyway keeps
# the three create_conda_env_* scripts identical and costs nothing.
#
# CPU-only torch: the extra index below serves the `+cpu` builds, which avoids
# pulling ~2.5 GB of bundled CUDA libraries on Linux/Windows.
# -----------------------------------------------------------------------------
--extra-index-url https://download.pytorch.org/whl/cpu
